# Product Price Above Average Transaction Total

---

## Business Context

This is a common **product and transaction analytics** problem.

Businesses may compare the listed price of a product against the average transaction value generated by that product across all transactions.

This type of analysis can be used to:

* identify high-priced products,
* compare product pricing with actual transaction values,
* analyze purchasing behavior,
* identify products with relatively low transaction quantities,
* support pricing and product-performance analysis.

The same SQL pattern is useful when comparing a **row-level attribute** such as product price against an **aggregate metric** calculated across the entire transaction dataset.

---

## Problem Statement

Given the `products` and `transactions` tables, return:

```text
product_id
product_price
avg_transaction_total
```

where:

```text
avg_transaction_total
=
average of (price × quantity) across all transactions
```

Only return products where:

```text
product_price > avg_transaction_total
```

The values should be rounded to **two decimal places**.

---

## Input Tables

### products

| Column  | Type    |
| ------- | ------- |
| `id`    | INTEGER |
| `name`  | VARCHAR |
| `price` | FLOAT   |

### transactions

| Column       | Type     |
| ------------ | -------- |
| `id`         | INTEGER  |
| `user_id`    | INTEGER  |
| `created_at` | DATETIME |
| `product_id` | INTEGER  |
| `quantity`   | INTEGER  |

---

## Expected Output

| Column                  | Type    |
| ----------------------- | ------- |
| `product_id`            | INTEGER |
| `product_price`         | FLOAT   |
| `avg_transaction_total` | FLOAT   |

---

# 1. Understand the Requirement

We need to calculate the **average transaction total across all transactions**.

For every transaction:

```text
transaction total = product price × quantity
```

Then:

```text
average transaction total
=
AVG(price × quantity)
```

This is **one overall average**, not a separate average for each product.

Finally, compare every product's price against that overall average:

```text
product price > average transaction total
```

Only products satisfying this condition should be returned.

The main challenge is:

> Calculate one aggregate value across all transactions and compare every product against that same value.

---

# 2. Understand the Table

| Table          | Purpose                                    | Important Columns        |
| -------------- | ------------------------------------------ | ------------------------ |
| `products`     | Stores product information and prices      | `id`, `price`            |
| `transactions` | Stores product transactions and quantities | `product_id`, `quantity` |

The important columns are:

```text
products.id
products.price
transactions.product_id
transactions.quantity
```

---

# 3. Clarify the Grain

### `products` table grain

One row represents:

> One product.

### `transactions` table grain

One row represents:

> One transaction for a product.

### Output grain

One row represents:

> One product whose price is greater than the overall average transaction total.

---

# 4. Identify Relationships

The tables are connected using:

```text
products.id
     ↓
transactions.product_id
```

Relationship:

```text
products
    │
    │ product_id
    ↓
transactions
```

We need this relationship because:

* `products` contains the **price**
* `transactions` contains the **quantity**

Therefore, we need both tables to calculate:

```text
price × quantity
```

---

# 5. Determine the Driving Table

There are actually **two logical steps** in this problem.

### Step 1 — Calculate the overall average

We use both tables:

```text
products
    ↓
transactions
    ↓
price × quantity
    ↓
AVG()
```

This produces **one value**:

```text
avg_transaction_total
```

### Step 2 — Compare every product

The `products` table becomes the driving table for the final output because we need to evaluate each product's:

```text
price
```

against the calculated average.

Conceptually:

```text
All Transactions
      ↓
Calculate Overall Average
      ↓
Compare Every Product
      ↓
Keep price > average
```

---

# 6. Think About Join Type

For calculating the average, we use:

```sql
JOIN transactions t
    ON t.product_id = p.id
```

An `INNER JOIN` is appropriate because the average is calculated from **transactions**, and products without transactions do not contribute a transaction total.

Then, in the final query, we attach the single average value to every product.

The original solution uses:

```sql
JOIN c1 ON 1 = 1
```

This creates a **CROSS JOIN-like effect** because `c1` contains exactly one row.

A clearer way to express the same idea is:

```sql
CROSS JOIN c1
```

---

# 7. Find the "No Match" / Required Condition

The first calculation is:

```sql
AVG(p.price * t.quantity)
```

This produces the overall average transaction total.

For example, if transaction totals are:

```text
160
120
200
166
```

then:

```text
AVG = 161.50
```

We then compare every product price against:

```text
161.50
```

The required condition is:

```sql
price > avg_transaction_total
```

Notice that the condition is **strictly greater than**.

Therefore:

```text
price = average → Exclude
price > average → Include
price < average → Exclude
```

---

# 8. Interpret the Conditional Logic

The core comparison is:

```sql
WHERE p.price > c1.avg_transaction_total
```

The logic is:

```text
             Product Price
                  ↓
        Compare with Average
                  ↓
        ┌─────────┴─────────┐
        ↓                   ↓
     Greater              Not greater
        ↓                   ↓
     Include               Exclude
```

The average itself is calculated using:

```sql
ROUND(AVG(p.price * t.quantity), 2)
```

So the reported average is rounded to two decimal places.

---

# 9. Final Calculation Logic

### Step 1

Join products with transactions.

```sql
FROM products p
JOIN transactions t
    ON t.product_id = p.id
```

### Step 2

Calculate the transaction total:

```sql
p.price * t.quantity
```

### Step 3

Calculate the overall average:

```sql
AVG(p.price * t.quantity)
```

### Step 4

Round the average:

```sql
ROUND(AVG(p.price * t.quantity), 2)
```

### Step 5

Store this single value in a CTE:

```text
transactions
      ↓
price × quantity
      ↓
AVG()
      ↓
avg_transaction_total
```

### Step 6

Compare every product price with that value:

```sql
p.price > avg_transaction_total
```

Final flow:

```text
Products + Transactions
          ↓
   price × quantity
          ↓
    Overall AVG
          ↓
   Round to 2 decimals
          ↓
 Compare every product price
          ↓
 price > average?
          ↓
        Output
```

---

# 10. SQL Solution

```sql
WITH c1 AS (
    SELECT
        ROUND(AVG(p.price * t.quantity), 2) AS avg_transaction_total
    FROM products p
    JOIN transactions t
        ON t.product_id = p.id
)

SELECT
    p.id AS product_id,
    p.price AS product_price,
    c1.avg_transaction_total
FROM products p
CROSS JOIN c1
WHERE p.price > c1.avg_transaction_total;
```

---

### Key takeaway

This is a classic **aggregate-then-compare** SQL problem.

When you see:

> Calculate one overall metric and compare individual records against that metric.

Think:

```text
1. Calculate the aggregate
2. Store it in a CTE/subquery
3. Attach it to the main dataset
4. Compare individual rows against the aggregate
5. Filter the results
```
